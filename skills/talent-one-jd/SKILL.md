# Talent One: job description with annotation rail

Build artifact 02 (job description with annotation rail) via the Talent One agent pipeline. You never write artifact content yourself.

## Procedure

1. **Profile gate.** Look for `onepromptman-profile.md` in the working folder. Missing: offer setup (invoke `talent-one-setup`) or the quick path (collect only what this artifact needs, label assumptions). On the quick path, ALWAYS ask which company this search is for via AskUserQuestion; chat history and memory are not valid sources for company identity, though they may seed the options. Present: read it and confirm its company is the right one for this search in one line.
2. **Plan.** Create or reuse the role home `talent-one-roles/<role_slug>/` with `inputs/` and `content/`, and the run folder `runs/<YYYY-MM-DD>/` with its own `content/`. Legacy `talent-one-runs/` folders stay readable. Before spawning relay, invite materials once in one plain message, never a chip question: paste or attach a JD, intake notes, comp data, or a straight brain dump, or say skip; attached files go into `inputs/` unchanged, pasted text becomes `inputs/braindump-<YYYY-MM-DD>.md` verbatim. Mention, once, the fastest option: pasting `../talent-one/references/PACK_RESEARCH_PROMPT.md` into any Claude chat (claude.ai, the app, or a second Cowork tab) and dropping the returned JSON into `inputs/` gives scout a ready pack to import, optional, never required over the role spec. Spawn `talent-one:relay` with `mode: plan` plus the requested artifact (02), role home, run folder, profile, per-run inputs, and available connectors. Relay plans only; it spawns nothing. It returns the pack plan (reuse / sectional refresh / build / import / migrate), the preflight report, one consolidated ask-first list, and seed proposals. Put those to the user in ONE AskUserQuestion pass; blocking items gate execution.

2.5. **Format and source, in the same ask.** In the one AskUserQuestion pass that carries relay's ask-first list, add two items: which format they want (branded HTML, HTML plus markdown, HTML plus docx), and whether they already have a JD or intake doc for this role. If they do, copy the file into `inputs/` and tell relay it is there; accept pasted text too, written to `inputs/braindump-<YYYY-MM-DD>.md` verbatim, invited in one plain message rather than expecting a file. A supplied JD seeds pack paths per `../talent-one/references/CONTEXT_PACK.md` §6 and becomes the intake draft the calibration ledger diffs against; it shortens the pack build, it does not skip the market read.

3. **Execute.** For every seed the user accepted, write it into the pack yourself first (§6: provenance floor, `constraints` verbatim from the profile only), validate with `render.py validate-pack`. Spawn `talent-one:relay` with `mode: execute` plus the same inputs, the user's answers or waivers, and (inside JD-BOT's per-run inputs) `plain_doc: markdown|docx|both` when asked plus the supplied JD's full path if there is one; it spawns `talent-one:scout` if the plan calls for it, spawns `talent-one:jdbot` (writing `content/02.content.json` and, when `plain_doc` is set, the posting markdown beside it, never HTML), spawns `talent-one:critic` and routes repair patches, renders and verifies deterministically via Bash exactly as `agents/relay.md`'s Phase 3 documents (`--strict`; a render error, a `--strict` failure, or a verify HIGH routes back to `talent-one:jdbot` as a content patch, never hand-edited HTML), and returns the completion report. Convert markdown to docx yourself if asked (pandoc, else the `docx` skill; if neither is available, deliver the markdown and say so plainly); never retype the posting. A single-artifact run never triggers qa-gate (relay's Phase 4 needs 2 or more artifacts). If relay instead returns a consolidated ask block (some agent inside it halted on `ask_user`), put it to the user in one pass and re-invoke `mode: execute` with the answers; never leave an ask unanswered and re-spawn. Deliver the rendered file (and the markdown or docx, if built) with SendUserFile (then create_artifact per the orchestrator's delivery convention), and copy the content JSON to the role home's `content/` cache. Then say in one line that it is a first draft and offer the customization walkthrough (`talent-one-setup` step 8).
4. **Self-QA travels with the agent** (00_SHARED_CORE.md §7) and the verify report covers the machine layer; the full qa-gate runs only for multi-artifact packages or on request. Updates to an existing artifact for this role follow the orchestrator's update mode: patch pack or content, re-render, never a full rerun.

## Non-negotiables

Constraints render verbatim from the profile; empty constraints means no eligibility gate. Three-pill honesty vocabulary only. "TBD", "N/A", "to be confirmed", and any other hedged placeholder are QA failures wherever they appear, including a one-row repeat that stands in for the missing others; the honest empty state is an omitted key or an empty repeat list, never a hedge. No em dashes. Company facts come from the profile or live research, never invention. Authoritative references live in the `talent-one` skill: `../talent-one/references/00_SHARED_CORE.md`, `CONTEXT_PACK.md`, `02_GROUNDING_MATRIX.md`, and `ADAPTATIONS.md` (the content/render-split items define the 1.0 pack-and-render pipeline).
